# ファクトチェック（事実確認）

## このスキルの目的

ユーザーがファクトチェックを求めるのは、もっともらしく聞こえる情報をそのまま信じたくないからです。したがって、このスキルの価値は「自信ありげに答えること」ではなく「確認できたこと・確認できなかったことを正直に分けること」にあります。検索してもわからなかった場合に、記憶だけで埋めて断定してしまうと、このスキルの存在意義がなくなります。わからないことは「わからない」「確認できなかった」と明記してください。

## 手順

### 1. 対象を確定する

- チャットに直接書かれた主張・文章 → そのまま対象にする。
- アップロードされた文書（PDF・Word・記事など） → Read ツール（必要に応じて pdf / docx スキル）で内容を取得する。
- URL → まず WebFetch で取得する。JavaScript 描画で中身が取れない場合は、無理に他の手段で回避しようとせず、取得できた範囲で判断するか、その旨をユーザーに伝える。

対象文章が長すぎる、もしくは「どの主張を検証すべきか」が曖昧な場合（例：10ページの報告書全体など）は、勝手に範囲を絞らず、どの部分を重点的に見るかをユーザーに確認する。

### 2. 検証可能な主張を洗い出す

文章を、個別に真偽を判定できる「主張」の単位に分解する。対象になりやすいもの：

- 数値・統計（金額、割合、件数など）
- 日付・時系列（いつ起きたか、いつまでに、など）
- 固有名詞（人物、組織、役職、製品名、地名）
- 引用・発言（誰が何と言ったか）
- 法令・制度・規則に関する記述
- 因果関係の主張（「AだからBが起きた」）
- 現在の状態に関する主張（現職者、最新価格、最新バージョンなど。これらは特に時間が経つと変わるため必ず検索で確認する）

単なる意見・感想・主観的評価（例：「このデザインは美しい」）は検証対象外として、その旨を明記するだけでよい（無理に真偽判定しない）。該当する意見・主観がない場合は、この区分自体を出力に含める必要はない。

論理的に結びついた複合的な主張（例：「AはBより多く、Cが2位だ」のような順位比較）は、無理に細分化せず、ひとまとまりの主張として扱ってよい。分解の粒度に厳密な決まりはないので、読み手にとって自然な単位を優先する。

### 3. Web検索で裏取りする

抽出した主張ごとに WebSearch を使い、独立した信頼できる情報源を探す。目安：

- 一次情報源（公式統計、政府・自治体・企業の公式発表、当事者の一次発言、学術論文）を優先する。
- 二次情報源（報道）だけの場合は、複数の独立した媒体が一致しているかを確認する。
- 情報源の日付を確認する。現職者・価格・法令・最新版など時間で変わりうる情報は、検索結果が古くないか必ずチェックする。
- 検索しても信頼できる情報源が見つからない、または情報源同士が食い違う場合は、それをそのまま「検証不能」として扱う。無理に一つの答えに決め打ちしない。
- 一次情報源のページが文字化けする・JavaScriptで内容が取得できないなど技術的に読めない場合は、その一次情報源に固執せず、複数の独立した二次情報源（報道・データ集計サイトなど）で裏取りして進めてよい。
- 一次情報源の発行日がクエリの時点より古い場合（例：数年前の統計発表など）は、その後の状況が変わっていないか、より新しい二次情報源で補強確認する。

### 4. 主張ごとに判定する

主張ごとに次の4項目を用意する。

- **判定**：正しい／誤り／一部正しい（要注釈）／検証不能
- **根拠区分**：以下の3つのいずれか
  - 確立した事実 … 独立した複数の信頼できる情報源、または確度の高い一次情報源で確認できた
  - 合理的な推論 … 直接の裏付けは見つからないが、確認済みの事実から論理的に導ける
  - 推測・不明 … 判断材料が不足している、情報源が対立している、または全く見つからない
- **情報源**：`[タイトル](URL)` の形式で列挙。検索していない・見つからない場合はその旨を書く
- **備考**：時間とともに変わりうる情報への注意、解釈の分かれ目、留意点など

アルファベットの略語・専門用語が出てきた場合は、初出時に正式名称（必要なら日本語訳）を併記する。

### 5. チャット内に構造化して回答する

次のテンプレートに沿って提示する（主張の数に応じて増減してよい）。

```
## ファクトチェック結果

### 主張1:「(原文の主張をそのまま引用)」
判定: ✅ 正しい / 🟡 一部正しい / ❌ 誤り / ❓ 検証不能
根拠区分: 確立した事実 / 合理的な推論 / 推測・不明
説明: (なぜその判定になったかを簡潔に)
情報源: [タイトル](URL), [タイトル](URL)
備考: (あれば。特に時間で変わりうる情報への注意)

### 主張2: …
（以下同様）

## 総括
検証した主張のうち、正しい: n件 / 一部正しい: n件 / 誤り: n件 / 検証不能: n件。
(全体として何が言えるか、特に注意すべき点があれば1〜2文で)
```

意見・主観として検証対象外にした部分があれば、総括の後に「検証対象外（意見・主観）」として簡潔に触れる。

### 6. 曖昧・不確実な場合の姿勢

- 確信が持てない場合は断定せず、「確実ではありませんが」「〜の可能性があります」のように明示する。
- 記憶に基づく知識と検索で確認した事実は区別する。検索していないのに「事実」として断定しない。
- 現職者・最新価格・法令など時間で変わりうる情報は、「念のため最新情報を確認してください」と添えるのが基本だが、その強さは根拠の強さに応じて調整する。公式情報源＋長期間一致した報道など、根拠が十分に強い場合は軽く一言添える程度でよく、情報源が少ない・最近変わったばかりなど際どい場合ほど、この注意書きを強めにする。

## 依存関係

- **ソフトウェア**: なし
- **Pythonライブラリ / JSライブラリ**: なし
- **他のスキル**: なし（対象がPDF/Word文書の場合、内容取得の補助として `pdf-document-to-md` 等のスキルを併用することがあるが、必須ではない）
- **その他**: WebFetch / WebSearch などClaude Codeの標準ツールを使用
