# PDF文書 → Markdown 変換

段落主体のPDF文書を「構造化された日本語Markdown本文 + 該当位置に埋め込まれた図」
に変換する。読者がMarkdownだけを読めば、元のPDFを開かなくても内容を理解できる
状態がゴール。本文はテキストとして写し、図・グラフ・写真だけを画像として切り出して
本文中の元の位置に埋め込む（スライド用スキルと違い、ページ全体画像は使わない）。

## 出力構成

PDFごとに1フォルダを作る。画像パスは必ずMarkdownからの相対パスにする
（フォルダごと移動しても表示が壊れないようにするため）。

```
<出力先>/<PDF名>/
├── <PDF名>.md
└── images/
    ├── fig_p015_1.png   (15ページ目の1つ目の図)
    └── ...
```

出力先の指定がなければユーザーに確認するか、PDFと同じ場所に作る。
成果物フォルダには md と images/ 以外を置かない。作業用のページ画像
（`pages/`）とテキスト抽出は中間生成物なので、完成後に `pages/` は削除する。

## 手順

### 1. ページ画像・テキスト層・図候補を生成する

```bash
python3 <このスキルのパス>/scripts/extract.py pages input.pdf <出力先>/<PDF名> --dpi 150
python3 <このスキルのパス>/scripts/extract.py figures input.pdf <出力先>/<PDF名>
```

- `pages` は `pages/page_NNN.png`（作業用ページ画像）と、一時ディレクトリに
  ページごとのテキスト層（`page_NNN.txt`）を出力し、テキスト層の品質ヒントを表示する。
- `figures` は図・グラフ領域を自動検出して `images/fig_pNNN_M.png`（200dpi）に
  切り出し、検出一覧（ページ・ファイル名・座標）を表示する。
- 範囲指定は両方とも `--first`/`--last`。長い文書は指定された範囲だけ処理する。

**テキスト層の品質に注意すること。** スクリプトが「テキスト層が破損」と警告した場合、
抽出テキストは文字化けしており使えない。その場合はページ画像（またはPDF自体）の
視覚的な読み取りだけを情報源にする。警告がなくても、抽出テキストは2段組の順序や
ハイフネーション・合字が崩れていることが多いので、**常にページの見た目を正とする**。
抽出テキストは固有名詞・数値・URLの綴り確認の補助として使う。

**スキャンPDF（全ページが1枚の画像）の場合、`figures` は候補を検出できない。**
これは正常な動作なので、自動検出に固執せず、手順3の `crop` による手動切り出しに
直行する。テキスト層も空なので、本文はページ画像の視覚読み取りだけで書く。

### 2. 全体構成を把握する

Markdownを書き始める前に、まず文書全体の構成をつかむ。Readツールで元のPDFを
20ページずつ読む（`pages` パラメータ使用。生成したPNGを個別に読むより効率的）。
変換範囲が20ページ程度以下なら、この把握と手順4の執筆を1回の読みで兼ねてよい
（構成把握のためだけに読み直さない。速度に直結する）。

読みながら以下をメモする：

- 表紙情報（タイトル・著者・版・日付）と目次
- 章・節の見出し階層（番号付けの体系: 「3.2.1」など）
- 図表番号の体系（Figure 3 / 図3 / Table 1 など）と、どのページにどの図があるか
- ヘッダー・フッター・ページ番号などの「毎ページ繰り返される飾り」（本文から除外する）
- 文書全体の言語

### 3. 図候補を検品する

`figures` の検出は機械的な候補にすぎない。検出一覧を見ながら各 `fig_*.png` を
Readで開いて確認する。検品は1回のReadで複数画像をまとめて見てよい（1枚ずつ
往復すると遅くなる）。次のように仕分ける：

- **本物の図・グラフ・写真・回路図・フローチャート** → 採用。
- **表** → 画像は削除し、本文でMarkdownの表として再現する（複雑すぎてMarkdown表に
  できない場合のみ画像を採用）。
- **罫線・飾り・ロゴ・数式の一部などのゴミ** → 削除。
- **図の一部が欠けている／隣接する図・表・本文が1枚に混ざっている** → `crop` で
  切り直す（近接した要素は1クラスタに統合されやすい。切り直し後も必ずReadで
  確認し、欠けが残れば座標を調整して繰り返す）。

`crop` は作業用ページ画像（150dpi）上のピクセル座標で指定する。ページ画像をReadで
見て座標を見積もり、切り出した結果を必ずReadで確認して、欠けていれば座標を調整して
やり直す：

```bash
python3 <このスキルのパス>/scripts/extract.py crop input.pdf <出力先>/<PDF名> \
    --page 42 --box 100,350,980,900 --suffix m1
```

また、ページ画像を読んでいて検出一覧にない図（薄い写真・スキャン図版など）に
気づいたら、同じ方法で切り出して追加する。**本文に登場する図はすべて埋め込む**のが
原則で、自動検出の取りこぼしは検品でカバーする。

### 4. Markdownを書く（逐次ビルド）

長い文書を一度に書こうとしない。まず冒頭（タイトル・書誌情報・目次）を書いて
ファイルを作成し、その後10〜20ページ分ずつ、ページ画像（またはPDF）を読みながら
追記していく。途中で失敗してもやり直しが最小で済む。

#### 文書全体の形

```markdown
# 文書タイトル（日本語）

- 著者/発行元: ○○
- 元ファイル: input.pdf（全NNページ、変換範囲: p.X〜Y）

## 3. 章タイトル

### 3.2 節タイトル

本文の段落。原文の段落構造を保ち、自然な日本語に翻訳する。

![図3: 粘度と温度の関係](images/fig_p015_1.png)

*図3: 粘度と温度の関係。実線は実測、破線はモデル外挿。*
```

- 見出しレベルは元の章構造に対応させる（章=`##`、節=`###`、項=`####`）。
  `#` は文書タイトルのみ。元の章番号（3.2 など）は見出しに残す。
- ヘッダー・フッター・ページ番号・毎ページの飾りは本文に含めない。
- ページ境界で分断された段落・文はつなげて1つの段落にする（ハイフネーションで
  切れた単語も復元する）。改ページはMarkdown上では意味を持たない。

#### 図の埋め込み方

- 図は**原文で参照されている位置・本文の流れ上の元の位置**に置く。
- 画像の直後に、原文のキャプションを翻訳して斜体で添える。図番号
  （Figure 3 → 図3）は本文からの参照と対応が取れるよう必ず残す。
- キャプションのない図は、内容がわかる短い説明文を自分で書いて添える。
- 図の内容が本文の理解に不可欠な場合（グラフの傾向など）は、キャプションに
  1文だけ補足してよい。ただし図の中身の書き起こしはしない（画像で見えるため）。

#### 本文の書き方

- 段落は段落のまま写す。原文にない箇条書き化・要約はしない（このスキルは
  要約ではなく変換のためのもの。読者は本文全体を求めている）。
- 原文の箇条書き・番号付きリストはそのままリストに、表はMarkdownの表にする。
- 数式は LaTeX（`$...$` / `$$...$$`）で書く。式番号があれば `\tag{}` か
  行末に `(3.2)` の形で残す。
- コード・コマンド例はコードブロックにする。
- 脚注は Markdown の脚注記法（`[^1]`）にする。
- 強調（太字・斜体）は原文に従う。

#### 翻訳ルール

- 日本語以外のテキストはすべて自然な日本語に翻訳する。訳文のみを書き、
  原文は併記しない。
- ただし次は原語のまま残す：固有名詞（人名・組織名・製品名）、
  定着した技術用語、略語（初出時のみ
  「GNN（Graph Neural Network、グラフニューラルネットワーク）」の形で
  正式名称と訳を添える）、URL・コード・数式・変数名。
- もともと日本語の文書は翻訳せずそのまま整理する。

### 5. 検証する

書き終えたら必ず確認する：

```bash
# 画像参照と実ファイルの対応（参照漏れ・リンク切れの検出）
grep -o 'images/[^)]*\.png' <PDF名>.md | sort -u > /tmp/refs.txt
ls images/ | sed 's|^|images/|' | sort > /tmp/files.txt
diff /tmp/refs.txt /tmp/files.txt && echo OK
```

- images/ の全ファイルが本文から参照されているか（差分が出たら、参照忘れか
  検品での削除漏れ。どちらかを直す）
- 画像パスが相対パス（`images/...`）になっているか
- 見出し階層が飛んでいないか（`##` → `####` のようなスキップがないか）
- 未翻訳の外国語文が本文に残っていないか
- 作業用の `pages/` フォルダを削除したか

最後に数ページをサンプリングしてページ画像と本文を見比べ、段落の写し漏れ・
図の位置ずれ・誤訳がないかを確認する。

## 依存関係

- **ソフトウェア**: Python 3、poppler-utils（`pdftoppm` / `pdftotext` / `pdfinfo`）
- **Pythonライブラリ**: `pdfplumber`、`Pillow`
- **JSライブラリ**: なし
- **他のスキル**: なし
