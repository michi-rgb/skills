# 商品レビュー収集・要約

ユーザーが商品購入前に、実際の使用者の生の声を偏りなく把握できるようにする。
成果物は、複数の日本向けサイトのレビューを横断調査したうえでの、
**高評価・中評価・低評価の3層に整理した要約**。単に「評価が高い／低い」という
数字だけでなく、なぜそう評価されているのかという具体的な理由を示す。

このスキルの流れ：調査対象の確認 → 複数サイトからのレビュー収集 →
3層への分類・要約 → 出力 → 限界の明示。

## 対象外のケース

価格やスペックの横断比較が主目的で、レビュー内容の分析が主眼でない場合は、
このスキルではなく `shopping-research` スキルを使う。価格比較とレビュー要約の
両方が必要な場合は、両スキルの手順を組み合わせてよい。

## ステップ1 — 調査対象を確認する

検索を始める前に、以下を押さえる。

- 商品名（型番やブランドまで分かると精度が上がる）。
- 調査対象が1点の商品か、複数点の比較か。
- 複数点の場合、比較したい観点（総合的な満足度の違いか、特定の不満点の
  有無かなど）。

会話の文脈から分かる情報は聞き直さない。確認しないと調査の方向が変わって
しまう点だけを、1〜2個に絞って質問する。

## ステップ2 — 複数の日本向けサイトからレビューを収集する

単一サイトのレビューだけに頼らない。サイトによってレビューを投稿する
利用者層や傾向が異なるため、最低でも2〜3サイトを横断して調べる。

商品カテゴリに応じて選ぶ候補サイト：

- Amazon.co.jp のカスタマーレビュー
- 楽天市場のレビュー
- Yahoo!ショッピングのレビュー
- 価格.com のクチコミ掲示板
- ヨドバシ.com のレビュー（家電・パソコン等）
- 商品カテゴリに特化したレビューサイトや専門メディアのレビュー記事

サイトによって得意なことが違う：

- **価格.com（review.kakaku.com）・楽天市場（review.rakuten.co.jp）** は、
  クチコミページに星ごとの件数や満足度の平均点が明記されていることが多く、
  評価分布を数値で押さえたいときに向いている。
- **Amazon.co.jp** は個別レビューの中身（具体的な使用感）は豊富だが、
  検索結果のスニペットは商品一覧やフィルターパネルばかりで、星評価の分布
  そのものはスニペットから読み取れないことが多い。商品ページを直接
  web_fetch しようとすると、URLが長すぎて取得できなかったり、
  アクセスを拒否されたりすることがあるので、無理に1URLに固執せず、
  検索結果に出てくる個別レビューの引用（スニペット）を情報源として使う。
- レビューの信頼性チェックサイト（やらせレビュー検証サイトなど）は
  robots.txtで自動アクセスを拒否していることが多く、fetchできない前提で
  進める。検索結果のスニペットで得られる範囲の情報にとどめる。

進め方：

- 商品ごと・サイトごとに個別に検索する。まとめて1つのクエリで検索すると、
  どの商品についても浅い結果しか得られない。目安として商品1点につき
  3〜5回程度の検索で足りることが多い。まず「商品名＋レビュー／クチコミ」で
  全体像をつかみ、次に星評価の分布が取れそうなサイト（価格.com・楽天）を
  個別に検索し、最後に「商品名＋不満／星1／気になる点」のように低評価側を
  狙った検索を行うと、少ない回数で高評価・低評価の両方の材料が揃いやすい。
- 各サイトの星評価の分布（星5〜星1それぞれの件数や割合）と、レビュー
  総数を記録する。母数が極端に少ないサイトの結果は参考程度に留め、その旨を
  出力にも明記する。
- レビューの投稿日を確認する。旧モデルや旧バージョンのレビューが混在して
  いないか注意する。
- 検索・取得で実際に得られた情報だけを使う。存在を確認できていないレビュー
  やサイトを推測で作らない。数回検索しても星評価の分布や件数が確認できない
  商品・サイトがある場合、検索を延々と繰り返して粘るより、「確認できな
  かった」事実を記録して次に進む方が誠実で効率もよい（ステップ5で明記する）。

## ステップ3 — レビューを高評価・中評価・低評価の3層に分類する

分類の目安：

- 高評価：星5・星4、または各サイトの「おすすめ」「満足」に相当する評価。
- 中評価：星3、または「まあまあ」「一部不満」に相当する評価。
- 低評価：星1・星2、または「不満」「後悔」に相当する評価。

各層について、以下を整理する。

- その層で繰り返し言及されている具体的なポイント（機能・使い心地・耐久性・
  サポート対応など）。
- 感情的な一言（「最高」「がっかり」等）だけでなく、その背景にある具体的な
  理由。
- 1件だけの特殊な事情による極端な少数意見と、複数のレビューで共通して
  見られる傾向とを区別する。

著作権への配慮：

- レビュー本文をそのまま引用しない。要約は自分の言葉で行う。直接引用が
  どうしても必要な場合でも、1情報源につき1回・15語程度以内に留める。
- 「レビューを全文貼って」と頼まれた場合も、要約と傾向の提示にとどめ、
  全文転載はしない。

## ステップ4 — 出力する

**商品が1点の場合**

1. 商品名と、調査したサイト・件数の概要（表にする場合はセルの値を短く
   保つ。例：サイト名・平均評価・件数のみ。長い所感は表に入れず箇条書きで
   補う）。
2. 高評価の傾向（箇条書き3〜5項目）。
3. 中評価の傾向（箇条書き2〜4項目）。
4. 低評価の傾向（箇条書き3〜5項目）。
5. 総括（購入前に確認すべき点を1〜2文で）。

**商品が複数点の場合**

1. 比較対象の全商品をまとめた**1つの概要表**を先頭に置く（商品ごとに
   別々の表を作らない方が一覧性が高い）。列は価格・サイトごとの評価
   （分かるもの）など短い値に絞る。ある商品・サイトで件数や評価が
   確認できなかった場合は、空欄にせず「データ不足」のようにその旨を
   セルに明記する（分からないことを分かるふりをしない）。
2. 商品ごとに、高評価・中評価・低評価の傾向を上記2〜4と同じ形式で
   並べる。
3. 最後に「商品間の違い」を短くまとめる（打鍵感・機能・価格帯など、
   実際に差がついた観点を中心に。項目数が多くなりがちなので、表よりも
   箇条書きの方が読みやすい）。

## ステップ5 — 限界を明示する

最後に必ず以下を伝える。

- レビューの真正性は保証できない。やらせレビューやキャンペーン目的の
  高評価などが混じっている可能性がある。
- レビューの傾向は調査時点のものであり、商品の仕様変更やレビューの増減に
  よって変わりうる。
- 母数が少ないサイトの結果は参考程度であることを明記する。
- 比較する商品の間で、確認できた情報の量に差がある場合（例：一方は
  星評価の分布まで分かったが、もう一方は個別レビュー記事しか見つから
  なかった）は、その差自体を明記する。情報が少ない方の商品を実際より
  評価が低い・悪いかのように見せてしまわないよう注意する。

## 出力テンプレート例

```
(商品名) のレビュー傾向

調査対象：(サイト名を列挙)
レビュー合計件数：約(件数)件

【高評価の傾向】
- ...
- ...

【中評価の傾向】
- ...

【低評価の傾向】
- ...
- ...

総括：...

※ レビューは(調査日)時点の情報です。やらせレビューが混じっている可能性が
あるため、参考情報としてご活用ください。
```

複数点を比較する場合は、先頭に概要表を置いたうえで、上記の【高評価】
【中評価】【低評価】ブロックを商品ごとに並べ、末尾に「商品間の違い」の
箇条書きを追加する。

```
| 商品 | 実勢価格 | 評価の目安 |
|------|---------|-----------|
| (商品A) | (価格) | (分かれば件数・点数、不明なら「データ不足」) |
| (商品B) | (価格) | (分かれば件数・点数、不明なら「データ不足」) |

【(商品A) の高評価の傾向】
- ...

（商品Bも同様に高評価・中評価・低評価を並べる）

【商品間の違い】
- ...
```

## 例

**入力：**「このワイヤレスイヤホンのレビューをまとめて。買うか迷ってる」

**進め方：** 商品は1点なので、比較観点の確認は不要。Amazon.co.jp・
価格.com・楽天市場のレビューを個別に検索し、星評価の分布とレビュー件数を
記録する。高評価では音質と装着感への言及が多い、中評価では価格相応という
声が多い、低評価では特定の環境でのBluetooth接続の不安定さが繰り返し
指摘されている、といった形で3層に整理する。最後に、レビューの真正性や
調査時点の限界を明記して締めくくる。

**入力：**「キーボードAとキーボードBのレビューを比較して」

**進め方：** 商品が2点なので、先頭に価格・評価の概要表を置く。片方の
商品（発売から時間が経ち定番化している方）は価格.comや楽天のクチコミ
ページに星評価の分布まで載っていて数値化しやすいが、もう片方（発売間もない、
またはニッチな商品）はAmazon.co.jpの検索結果がフィルターパネルばかりで
分布が読み取れず、個別のブログ・レビュー記事しか材料が集まらないことがある。
このとき、無理に数字を作ったり、材料が少ない方を検索し直して粘ったりせず、
概要表のセルに「データ不足」と明記したうえで、集まった個別レビューの内容
だけで高評価・中評価・低評価を質的に整理する。最後の限界セクションでも、
「商品間で確認できた情報量に差がある」旨を明示し、材料が少ない方を実際より
低評価であるかのように誤読されないようにする。

## 依存関係

- **ソフトウェア**：なし。
- **他のスキル**：なし（価格・スペック比較が主目的の場合は
  `shopping-research` を案内する旨の記載はあるが、これは対象外ケースの
  切り分けであり本スキルの依存ではない）。
- **その他**：WebSearch / WebFetch などの標準ツールを使用する。
