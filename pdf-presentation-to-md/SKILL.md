# PDFプレゼン → Markdown 変換

PDFのスライド資料を「ページ画像 + 構造化された日本語テキスト」のMarkdownに変換する。
読者がMarkdownだけを読めば、元のスライドを見なくても内容を理解できる状態がゴール。
画像は見た目の再現、テキストは検索・引用・流し読みのためにある。

## 出力構成

PDFごとに1フォルダを作る。画像パスは必ずMarkdownからの相対パスにする
（フォルダごと移動しても表示が壊れないようにするため）。

```
<出力先>/<PDF名>/
├── <PDF名>.md
└── images/
    ├── page_001.png
    ├── page_002.png
    └── ...
```

出力先の指定がなければユーザーに確認するか、PDFと同じ場所に作る。
成果物フォルダには md と images/ 以外を置かない（テキスト抽出などの中間生成物は
一時ディレクトリに置く。スクリプトは既定でそうする）。

## 手順

### 1. ページを画像化し、テキスト層を抽出する

```bash
python3 <このスキルのパス>/scripts/convert_pages.py input.pdf <出力先>/<PDF名> --dpi 150
```

スクリプトは `images/page_NNN.png`（150dpi PNG）を成果物フォルダに、
`page_NNN.txt`（テキスト層の抽出結果）を一時ディレクトリに生成し、
総ページ数・テキスト出力先・テキスト層の品質ヒントを表示する。ページ数が多い場合も一括で実行してよい
（画像化は速い）。`--first`/`--last` で範囲指定もできる。

**テキスト層の品質に注意すること。** スクリプトが「テキスト層が破損」と警告した場合、
抽出テキストは文字化けしており使えない。その場合はページ画像（またはPDF自体）の
視覚的な読み取りだけを情報源にする。警告がなくても、抽出テキストは順序や
グルーピングが崩れていることが多いので、**常にページの見た目を正とする**。
抽出テキストは固有名詞・数値・URLの綴り確認の補助として使う。

### 2. ページを読んで全体構成を把握する

Markdownを書き始める前に、まず資料全体の構成をつかむ。Readツールで元のPDFを
20ページずつ読む（`pages` パラメータ使用。生成したPNGを個別に読むより効率的）。

読みながら以下をメモする：

- タイトルページ（発表題目・発表者・日付）
- 目次・アジェンダページ
- **セクション区切りページ**（章タイトルだけの中扉スライド）— これが章構造の根拠になる
- 資料全体の言語

セクション区切りが明示されていない資料でも、話題の変わり目から章立てを推定してよい。
ただし推定した章名は資料内の言葉を使い、勝手な創作はしない。

### 3. Markdownを書く（逐次ビルド）

長い資料を一度に書こうとしない。まず冒頭（タイトル・概要・目次）を書いてファイルを
作成し、その後10〜20ページ分ずつ追記していく。こうすると途中で失敗しても
やり直しが最小で済み、ページの読み込みと執筆を交互に進められる。

#### 文書全体の形

```markdown
# 資料タイトル（日本語）

- 発表者: ○○
- 日付: YYYY-MM-DD
- 元ファイル: input.pdf（全NNページ）

## 第1章 セクション名

### スライドのタイトル

![p.3](images/page_003.png)

- 要点1
- 要点2
    - 補足
```

- `#` は資料タイトルのみ。セクション（章）は `##`、各スライドは `###`。
  資料の階層が深い場合は `####` まで使ってよい。
- セクション区切りの中扉スライドは、`##` 見出し + 画像のみでよい（本文は不要）。
- **必ず「画像が先、テキストが後」の順**。ユーザーは画像でスライドを見て、
  直下のテキストで内容を読む、という流れで使う。
- 全ページの画像を順番どおりに漏れなく埋め込む。飛ばしてよいのは白紙ページのみで、
  その場合も `（p.42 は白紙）` のように断り書きを入れる。

#### 各ページのテキストの書き方

- スライドの構成を反映して整理する：スライド内の箇条書きは箇条書きに、
  階層はネストに、表は Markdown の表に、コードはコードブロックにする。
- 図・グラフ・写真が主体のスライドは、内容を1〜3文で説明する
  （例：「横軸にモデルサイズ、縦軸に精度を取った散布図。サイズが大きいほど〜」）。
- 発話の書き起こしではなくスライドの書き起こしなので、スライドに書かれている
  情報を過不足なく写すことを優先し、解説の付け足しは最小限にする。
- 数式は LaTeX（`$...$` / `$$...$$`）で書く。
- **段階的ビルドアップスライド**（前ページと同じ内容に要素が少しずつ追加されて
  いく連続ページ）では、共通部分を毎ページ書き写さない。最初のページで全体を
  説明し、以降のページは「追加された要素」だけを1〜2文で書く。読者は直前の
  ページを読んだばかりなので、重複記載はノイズにしかならない。

#### 翻訳ルール

- 日本語以外のテキストはすべて自然な日本語に翻訳する。訳文のみを書き、
  原文は併記しない（原文はすぐ上の画像で確認できるため）。
- ただし次は原語のまま残す：固有名詞（人名・組織名・製品名）、
  定着した技術用語（例: Transformer, attention）、略語（初出時のみ
  「GNN（Graph Neural Network、グラフニューラルネットワーク）」の形で
  正式名称と訳を添える）、URL・コード・数式。
- もともと日本語のスライドは翻訳せずそのまま整理する（日英混在の資料では
  ページごとに判断する）。

### 4. 検証する

書き終えたら必ず確認する：

```bash
# 画像参照の数・順序と実ファイルの対応を確認
grep -o 'images/page_[0-9]*\.png' <PDF名>.md | sort | uniq > /tmp/refs.txt
ls images/ | sed 's|^|images/|' > /tmp/files.txt
diff /tmp/refs.txt /tmp/files.txt && echo OK
```

- 全ページが順番どおり参照されているか
- 画像パスが相対パス（`images/...`）になっているか
- 見出し階層が飛んでいないか（`#` → `###` のようなスキップがないか）
- 未翻訳の外国語文が本文に残っていないか

数ページをサンプリングして画像と本文を見比べ、内容の写し漏れ・誤訳がないかも確認する。

## 依存関係

- **ソフトウェア**: Python 3、poppler-utils（`pdftoppm` / `pdftotext` / `pdfinfo`）
- **Pythonライブラリ**: なし（`scripts/convert_pages.py` は追加のpip依存なしで動作）
- **JSライブラリ**: なし
- **他のスキル**: なし
