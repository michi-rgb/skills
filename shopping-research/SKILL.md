# ショッピングリサーチ・比較

ユーザーが自信を持って購入を決断できるよう、複数の情報源を調査し、誠実で分かり
やすい比較を提示する。成果物は **チャット内でのMarkdown比較表**と、ユーザーの
実際のニーズに合わせた**短い推奨コメント**。

このスキルの流れ：ニーズの把握 → 複数の実在する情報源の調査 → 一貫した基準での
比較表作成 → 推奨 → 確認すべき点の明示。

## 対象外のケース

MISUMI(ミスミ)の通販サイトでFA部品・金型部品・切削工具などを探していて、
「どのカテゴリを見ればいいか分からない」といったサイト構造のナビゲーションが
主目的の場合は、このスキルではなく `misumi-navigator` スキルを使う。本スキルは
一般的な商品比較・購買判断が目的の場合に使う。

## このスキルが必要な理由

買い物中のユーザーが求めているのは大量のリンクの羅列ではなく、自分の状況に合った
数個の選択肢を、同じ基準で並べて、注意点まで含めて見せてもらうことである。価格や
在庫は常に変動し、学習データの時点とはずれているため、Claudeが付加価値を出せるのは
「もっともらしい推測」ではなく「誠実で出典のある最新の調査」である。価格やスペックを
間違えることは、「確認できませんでした」と正直に言うことより、はるかに信頼を損なう。

## ステップ1 — ニーズを手短に確認する

検索を始める前に、絞り込みに必要な情報を押さえる。

- **何を**買うか（カテゴリ＋必須の機能・条件）
- **予算**の上限（あれば）
- **用途**（何のために使うか。どのスペックを重視すべきかが決まる）
- **譲れない条件**（サイズ、ブランド、対応エコシステム、地域・配送可否）

まずは会話の文脈から推測する。ユーザーが既に予算や用途を伝えていれば聞き直さない。
聞くのは、それを確認しないと推奨内容が変わってしまう場合のみとし、質問は1〜2個に
絞る。「〜という前提で進めます（違えば教えてください）」のように、妥当な前提を
明示する方が、根掘り葉掘り質問するより望ましい。

## ステップ2 — 複数の実在する情報源を調査する

単一の販売店や記憶だけから比較表を作らない。価格・型番・在庫は学習データの
カットオフ後に変わっているため、必ず検索ツール（WebSearch / WebFetch など）を
使って実際に調べる。

デフォルトはユーザーの地域に合わせる。日本のユーザーであれば、Amazon.co.jp、
楽天市場、Yahoo!ショッピング、価格.com、ヨドバシ.com、カテゴリ別のレビュー
サイトなどを使う。他の地域の場合は、その地域の主要な販売店・比較サイトと現地
通貨を使う。地域が不明な場合は質問するか、前提を明示する。

調査の進め方：

- **候補商品ごと・主要な情報源ごとに個別に検索**する。まとめて一つのクエリで
  検索すると、どの商品についても浅い結果しか得られない。
- **価格・主要スペックは販売店から**、**長所・短所や信頼性は独立したレビュー**
  （専門メディアのレビュー、集約されたユーザー評価）から取得する。特定の販売店の
  宣伝文句だけを情報源にしない。
- 候補は**2〜5件**程度に絞る。5件を超えると表が実用的でなくなる。
- 各価格の**取得日と出典**を記録し、後で出典を示し、情報の鮮度を明示できるように
  する。
- 出典として提示するURLは、検索・取得で実際に得られたものだけを使う。存在を
  確認できていないURLを推測して作らない。

特定の数値（価格・正確なスペック）が出典から確認できない場合は、記憶で埋めずに
表内で「価格未確認」などと明記する。

## ステップ3 — 比較表を作成する

すべての候補に**同じ基準（列）**を使い、真に比較可能にする。基準はユーザーの
用途に合わせて選ぶ。列は固定ではないが、典型的には以下のようなもの：

| 項目 | 内容 |
|------|------|
| 価格 | 確認できた最安値と、確認した店舗・日付 |
| 主要スペック | 用途に直結する2〜4項目だけ（盛り込みすぎない） |
| 長所 | レビューや仕様から見た強み |
| 短所・注意点 | 弱点、隠れたコスト、在庫リスク |
| 評価 | レビュー傾向（出典つき） |

候補を**行**、基準を**列**にする（基準が多く候補が少ない場合は転置してもよい）。
セルは短く一目で分かるようにし、価格やレビューの主張には出典（可能なら
Markdownリンク）を添える。

## ステップ4 — ニーズに合わせて推奨する

表だけではユーザーに判断を丸投げすることになる。状況ごとに選択肢を対応づける
短い結論を添える。例：

- **総合おすすめ** — 述べられたニーズに最も合う選択肢
- **コスパ重視** — 予算を優先するならこれ
- **予算度外視** — 品質のために予算を伸ばせるならこれ

それぞれ1〜2文で理由を説明し、比較内容に基づかせる。**確認できた事実**（検証可能な
スペック・価格）と**判断**（Claudeの推奨）を区別し、どこからが意見なのかユーザーに
分かるようにする。

## ステップ5 — 確認事項と限界を明示する

必ず最後に、簡潔で正直な注記を添える：

- **価格・在庫は変動する**。提示した数値は調査時点のものであり、購入前に
  販売店のページで最新の価格・在庫を確認するようユーザーに伝える。「現在の価格」
  と断定せず、確認を促す。
- **Claudeは購入を代行できない**。このスキルは調査と比較までを行い、購入自体は
  ユーザーが販売店で行う。決済情報の入力や注文の確定は行わない。
- 文脈なしに「結局どれが一番いいの」と聞かれた場合は、単一の勝者を決めつけず、
  代表的な2〜3のシナリオに応じたニュアンスのある回答をする。

## 出力テンプレート

以下の形（ユーザーの言語に合わせて見出しを調整）に従う：

```
（1〜2文：何を・どんな条件で比較したか）

| 商品 | 価格 | 主要スペック | 長所 | 短所・注意点 |
|------|------|------------|------|-------------|
| ...  | ...  | ...        | ...  | ...         |

**おすすめ**
- 総合: 〇〇 — 理由
- コスパ: 〇〇 — 理由

※ 価格・在庫は○月○日時点の調査結果です。購入前に各店舗ページで最新の価格・
在庫をご確認ください。
```

## 例

**入力：**「2万円くらいで在宅勤務用のワイヤレスイヤホンを探してる。ノイズ
キャンセリング重視」

**進め方：** 予算（約2万円）と重視点（在宅勤務の通話・集中用のANC）は既に
与えられているので聞き直さない。Amazon.co.jp・価格.com・楽天で現在の価格を、
専門レビューやユーザー評価でANC性能・マイク品質・装着感を個別に検索する。
3〜4件の候補を、価格／ANC性能／通話品質／装着感／バッテリーを列にした表に
まとめ、レビューの出典を示した上で、総合おすすめとコスパ重視の2案を提示し、
価格は本日時点であり購入前に再確認するよう伝える。

## 依存関係

- **ソフトウェア**: なし
- **Pythonライブラリ / JSライブラリ**: なし
- **他のスキル**: なし（MISUMIのカテゴリナビゲーションが目的の場合は `misumi-navigator` を使う旨の案内はあるが、これは対象外ケースの切り分けであり本スキルの依存ではない）
- **その他**: WebSearch / WebFetch などの標準ツールを使用
